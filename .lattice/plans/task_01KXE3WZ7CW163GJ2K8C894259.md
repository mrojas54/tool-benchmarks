# TB-31: --exclude-subagents is a silent no-op on the agentsview index path, and the Summary claims an exclusion that never happened

TB-29 fixed --exclude-subagents on the RAW path (is_subagent path detection). The
AGENTSVIEW path was never covered, and there the flag does nothing at all.

MEASURED (live archive, --agent claude --all --limit 40, 2026-07-13):

  raw path (TB-29 fix works):
    [none]                620 calls, fingerprint 332fff82da4be971
    [--exclude-subagents] 521 calls, fingerprint 5c3854a59d2c2641   <- moves, correct

  agentsview path (no-op):
    [none]                3251 calls, fingerprint 6d146170ac125aff
    [--exclude-subagents] 3251 calls, fingerprint 6d146170ac125aff  <- IDENTICAL

Identical call count AND identical corpus fingerprint with the flag on and off:
nothing was excluded. But the Summary still flips its provenance line to
'Subagents included: no' -- an unearned claim. The report asserts an exclusion
that demonstrably did not occur.

ROOT CAUSE: shares TB-30's root cause. Without --include-children, agentsview never
LISTS subagent/child sessions, so no ref ever carries is_subagent=True and the
filter has nothing to remove. TB-29 hardened the predicate; this path never
receives the rows to apply it to.

NOTE ON ORDERING: fixing TB-30 (passing --include-children) is necessary but likely
not sufficient -- once child sessions are listed, is_subagent must actually be
derived for agentsview-sourced refs, which have path=None and so cannot use the
raw path's '<project>/<session-uuid>/subagents/' path-segment detection. The
agentsview row shape must supply the signal (e.g. a parent/child field on the
session-list JSON). Fix TB-30 first, then re-run this A/B: if the fingerprint still
does not move, the is_subagent derivation is the remaining gap.

FIX: after TB-30, derive is_subagent for agentsview refs from the session-list
payload, and assert in tests that --exclude-subagents moves the fingerprint on BOTH
index sources (the TB-29 test asserted on the FILTERED refs -- mirror that here).
The 'Subagents included:' provenance line should reflect what was actually filtered,
not merely which flag was passed.

Found by: operator smoke checkpoint CP3 (EVALUATION.md), 2026-07-13.

## Plan (as built) — PR #53

### The filed fix is not implementable
The ticket proposed deriving `is_subagent` from "a parent/child field on the session-list
JSON". No such field exists. Every candidate predicate was validated against ground truth
(the exact set difference between `--include-children` on and off, 923 real children):

    source_session_id != id        TP 915/923, FP 1631   <- also fires on resumed/compacted
                                                            sessions; would have misclassified
                                                            1631 legitimate top-level sessions
    id ~ ^(scheme:)?agent-         TP 915/923, FP    0   <- precise, but misses 7 codex
                                                            subagents carrying neither an
                                                            agent- token nor a parent pointer

### What was built instead
The listing runs TWICE — once with `--include-children` withheld (`_PROBE_INCLUDES`) — and
the difference between the two listings is the set of children, *by agentsview's own
definition*. Zero FP, zero FN, catches the codex 7, survives an id-scheme change. Cost is
one metadata-only pass (~5s for the full 11.9k archive, proportionally less for any scoped
run, since the probe inherits the same `--agent`/`--project`/`--since` filters).

Both passes MUST carry identical filters, or the difference is taken across two populations
and mislabels every ref. Pinned by test.

### Why truthful stamping at discovery is mandatory
`freeze` persists `is_subagent`, and freeze.py's stale-`false` self-heal can only fall back
to the PATH — which agentsview refs do not have (`path=None`). Leave the stamp false and
every frozen agentsview corpus keeps `--exclude-subagents` lying on replay forever.

### Provenance
`- Subagents included:` rendered straight from the CLI flag. It now reports the count
actually stamped at discovery, so a `no` beside `0 of N` says the index found no subagents
— not that the filter did its job.

### Caution on this ticket's original evidence
The filed A/B used `--limit 40`. The 40 most-recent claude sessions contain ZERO subagents
(first child sits at recency position 93), so that experiment could not have moved the
fingerprint whether or not the filter worked. The diagnosis was right; the experiment was
not decisive. The regression test now pins a window that actually contains children.
