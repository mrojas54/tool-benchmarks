Rationale: This is a plain stale relative-import specifier (a directory-rename half-applied to one of its two importers) that fails at ESM module-resolution time, before any application code runs. The failure mode is about as self-locating as a defect can be: Node's `ERR_MODULE_NOT_FOUND` error names the exact broken path in its own stack trace, so simply running the failing entrypoint once hands any tool the answer directly — no search strategy is required at all. A native grep for the import specifier, a serena `find_file`/symbol lookup on the same specifier, and a bash `rg` sweep are all trivially fast and equally cheap here; there is no graph to traverse and no ambiguity a symbolic index would resolve that text search wouldn't, and no volume of text a grep would have to wade through that a language server usefully prunes. None of the three toolsets has a structural advantage.
